# 3d_stokes_pigp.py — Code Documentation

*As of 2026-11-26. Structure follows the UC Berkeley Library guide "How to Write Good Documentation".*

## Overview

`3d_stokes_pigp.py` infers steady 3D Stokes flow in an x-periodic pipe with a physics-informed Gaussian process (PIGP), with no mesh and no flow data. It extends the 2D "Stokesian process" method of Molina et al. (2023) to 3D, to replicate Fujita-san's 3D work.

The Stokes and continuity equations are built into the GP covariance. The only training information is the no-slip wall, periodicity between x = 0 and x = L, the momentum equation with a constant body force, and div u = 0. The script then predicts u_x, u_y, u_z with an uncertainty (posterior standard deviation) anywhere in the pipe.

- **Geometry:** circular pipe of radius R(x) = width(x)/2, width(x) = 1 + 2a sin(2πx/L), period L = 2.5.
- **`--geometry pipe`** (default): straight pipe (a = 0), checked against the exact Poiseuille solution.
- **`--geometry sinusoidal`**: sinusoidal pipe (a = 0.2), checked against a 3D finite-element (FEM) reference from `fem_stokes_3d.py`, solved once and cached.
- **Status:** small test runs pass end to end; no full-size results yet.
- **Audience:** members of the PIGP project who run or modify the code.

## Requirements and installation

The script needs Python 3, four packages, and one helper file in the same folder.

| Requirement | Used for |
| --- | --- |
| `jax` (64-bit enabled inside the script) | kernels, automatic derivatives, Cholesky, jit |
| `jaxopt` | Nelder–Mead and L-BFGS-B (wraps SciPy) |
| `numpy` | post-processing and saving |
| `matplotlib` | PNG plots (Agg backend, no display needed) |
| `plotting_3d.py` in the same folder | `plot_plane` and `plot_profiles` |
| `fem_stokes_3d.py` in the same folder | FEM reference for the sinusoidal pipe |
| `scikit-fem`, `pyamg` (SciPy comes with them) | FEM reference; only needed for `--geometry sinusoidal` |

Install into the project with uv, from the repository root:

```bash
uv add jax jaxopt numpy matplotlib scikit-fem pyamg
```

On a GPU node, install `"jax[cuda12]"` instead of `jax`, matched to the node's CUDA version. Without it JAX falls back to the CPU and prints a warning.

If matplotlib cannot write to your home directory (seen on the cluster), set a writable config folder first:

```bash
export MPLCONFIGDIR=/tmp/$USER/mpl
```

## How to run

The script takes one optional argument, `--geometry`. Assuming it and `plotting_3d.py` sit in `src/workspace/stokes_flow/`, run from the repository root:

```bash
# straight pipe, compared with exact Poiseuille (default)
uv run python -u src/workspace/stokes_flow/3d_stokes_pigp.py

# sinusoidal pipe (a = 0.2)
uv run python -u src/workspace/stokes_flow/3d_stokes_pigp.py --geometry sinusoidal
```

| Argument | Values | Default | Effect |
| --- | --- | --- | --- |
| `--geometry` | `pipe`, `sinusoidal` | `pipe` | sets the wall amplitude a (0.0 or 0.2), the output folder, and the reference: exact Poiseuille or FEM |
| `--fem-refit` | flag | off | re-solve the FEM reference even if a matching cache exists |

`--help` lists the argument.

`-u` prints the optimizer progress live. The output folder is created next to the script, whatever folder you start it from.

The console shows, in order:

1. The setup: geometry, point counts, number of training rows (2792 with the defaults) and block order.
2. The initial objective and the time to compile it.
3. Nelder–Mead progress every 25 iterations, then whether the L-BFGS result was accepted.
4. A table of the optimized hyperparameters (amplitude A = e^γ and length scales per base kernel).
5. The error report, then the paths of the saved plots, `error_stats.txt` and `results.npz`.

Run time at full size is not measured yet. A small test (936 rows, 60 Nelder–Mead iterations) took about 70 s on one CPU. Each evaluation at full size needs a Cholesky of a 2792 × 2792 matrix plus rebuilding K, so 500 Nelder–Mead iterations should take hours on a CPU (estimate).

## Method

The velocity u = (u1, u2, u3) and pressure p get a joint GP prior. Every equation and boundary condition is a linear operator applied to it, so its covariance follows exactly from the base kernels.

### Equations

Steady Stokes flow with body force F = (12, 0, 0), written as in Molina et al. (eqs. 14–15):

```
f_α = ∂_α p − η ∇² u_α = F_α        (momentum, α = 1, 2, 3)
s   = ∇ · u = 0                     (continuity)
```

### Training data

Eleven blocks, in the order used for K and y:

| Block | Points | Condition | Rows |
| --- | --- | --- | --- |
| u1, u2, u3 | 384 wall points | u = 0 (no-slip) | 1152 |
| Su1, Su2, Su3 | 160 points on the x = 0 cross-section | u(x) − u(x + L) = 0 | 480 |
| Sp | same 160 points | p(x) − p(x + L) = 0 | 160 |
| f1, f2, f3 | 250 interior points | momentum = F | 750 |
| s | same 250 points | div u = 0 | 250 |
| **Total** | **794 distinct points** | | **2792** |

### Kernels and hyperparameters

Each base kernel is a 3D product squared exponential with its own log-amplitude γ and three length scales:

```
k(r, r') = exp( γ − (x−x')²/(2ℓx²) − (y−y')²/(2ℓy²) − (z−z')²/(2ℓz²) )
```

- **7 base kernels:** u1–u1, u1–u2, u1–u3, u2–u2, u2–u3, u3–u3, p–p, giving 28 hyperparameters stored as (γ, log ℓx, log ℓy, log ℓz) per kernel.
- **Velocity–pressure cross-covariance = 0:** Molina et al. mention this option but do not use it.
- **Derived covariances:** u–f, f–f, u–s, the periodic S blocks and so on are built from the base kernels by automatic differentiation, so they add no parameters.

### Objective

The hyperparameters minimize the negative log posterior: the GP negative log marginal likelihood plus Molina's Jeffreys prior (eq. 29), −log p = Σ log θᵢ over the positive parameters (A = e^γ, ℓ). In the stored variables this is `sum(theta)`.

### Optimization

Nelder–Mead runs first. L-BFGS-B then starts from its result and is kept only if it lowers the objective. Three safeguards keep both stable:

- **Failed Cholesky:** if K is not positive definite, the objective returns 10¹⁰ instead of NaN, so the optimizer steps away.
- **Scaled L-BFGS:** it works on z with θ = θ_NM + 0.01 z. Unscaled, its first trial step (length 1) made K indefinite and it stopped after 0 iterations.
- **Cross-component start:** u_a–u_b amplitudes start at γ = 0 instead of 1.2. With identical starting kernels the three wall blocks give identical rows and K is singular from the first evaluation.

## Reference solutions

| Geometry | Reference | Accuracy |
| --- | --- | --- |
| pipe | exact Poiseuille, u_x = F(R0² − r²)/(4η), u_y = u_z = 0; peak 0.75 | exact |
| sinusoidal | 3D FEM from `fem_stokes_3d.py` | about 0.2% of the peak velocity (estimate below) |

The straight-pipe solution follows from the x-momentum equation in cylindrical coordinates with ∇p = 0 (periodic pressure, fully developed flow), u finite on the axis and u = 0 at r = R0.

### FEM reference (fem_stokes_3d.py)

It solves the same problem the PIGP infers: same geometry, body force, no-slip wall, periodic u and p.

- **Mesh:** the unit-disk triangle mesh `MeshTri.init_circle(FEM_DISK_REFS)` is extruded along x into `FEM_NX` slices of prisms, each split into 3 tetrahedra; y and z are then scaled by R(x)/R0. Both end faces are identical, so periodic degrees of freedom pair exactly.
- **Elements:** Taylor–Hood P2 velocity / P1 pressure on tetrahedra (scikit-fem).
- **Periodicity:** degrees of freedom at x = L are identified with their partners at x = 0, the same method as the 2D `fem_stokes.py`.
- **No-slip:** every degree of freedom on the wall facets, found from the mesh topology.
- **Pressure:** fixed at one degree of freedom, then shifted to zero mean.
- **Solver:** MINRES with a block-diagonal preconditioner (one algebraic-multigrid V-cycle on the velocity block, lumped pressure mass).
- **Sampling:** the field is evaluated at all PIGP test points in one pass (volume, both planes, both profile lines). Points outside the faceted mesh would come back as NaN and are skipped in the statistics; none occurred in the tests.

**Caching.** The sampled values are saved to `output/sinusoidal/fem_reference.npz` with a fingerprint of the geometry, mesh settings and test points. Later runs load it in seconds; any change to those settings triggers a new solve, and `--fem-refit` forces one.

**Verification** (run on 2026-11-26, 2 CPU cores):

| Check | disk_refs 3, nx 32 (97k unknowns) | disk_refs 4, nx 64 (default) |
| --- | --- | --- |
| Straight pipe: max error vs Poiseuille, % of peak | 0.92% | 0.22% |
| Sinusoidal: max difference between the two meshes, % of peak u_x | 0.67% (u_x), 0.13% (u_y, u_z) | |
| Solve time | about 10 s | about 2 min |
| Peak memory | 0.9 GB | 5.7 GB |

The straight-pipe error falls by 4× when the mesh is halved (second order), so the sinusoidal error on the default mesh is about a third of the mesh difference, roughly 0.2% of the peak. The error comes mainly from the polygonal wall.

Run `python fem_stokes_3d.py` (options `--disk-refs`, `--nx`) to repeat the straight-pipe check.

## Code structure and API reference

The file runs top to bottom in nine sections; everything above the main driver only defines data and functions.

1. **Imports, command line and output folder:** 64-bit JAX; `--geometry`; `output/<geometry>/` and its `errors/` folder created next to the script.
2. **Exact solution:** `u_exact` (Poiseuille).
3. **Fluid and geometry:** `width`, `radius`, physical constants.
4. **Training points:** wall rings, periodic cross-section, random interior points.
5. **Kernels:** base kernel, operator combinators, the 7 base kernels, derived kernels.
6. **Kernel matrix:** the `kfn` table, `BLOCKS`, `y`, `build_K`.
7. **Objective and optimization:** negative log posterior, Nelder–Mead, L-BFGS-B.
8. **Prediction and diagnostics:** posterior mean and std, test grids, error and residual statistics, report writer.
9. **Main driver** (`if __name__ == "__main__":`): optimize, predict, plot, write the report, save.

### Functions

`R` is an (n, 3) array of points; `theta` is the 28-vector of hyperparameters.

| Function | What it does | Parameters | Returns |
| --- | --- | --- | --- |
| `Product_Squared_Exponential_Kernel` | base kernel value | `r`, `rp` points; `theta` 4-vector (γ, log ℓx, log ℓy, log ℓz) | scalar |
| `width`, `radius` | pipe diameter and radius | `x` | array like `x` |
| `sample_interior` | random points inside the pipe, uniform over each cross-section | `n`; PRNG `key`; `margin` (fraction of R) | (n, 3) array |
| `D`, `Dp`, `Lap`, `Lapp` | derivative or Laplacian on the first / second (primed) kernel argument | kernel `k`; axis `a` for `D`, `Dp` | kernel, or `None` if `k` is `None` |
| `S`, `Sp` | periodic difference k(r) − k(r + L e_x) on the first / second argument | kernel `k` | kernel or `None` |
| `add`, `mul` | sum of kernels; kernel times a constant | kernels; constant `c` | kernel or `None` |
| `kmat` | turns a point kernel into a matrix builder (zeros for `None`) | kernel `k` | function `(R1, R2, theta) -> matrix` |
| `kblock` | covariance block between two training kinds via `kfn` (transposes if only the reverse pair is stored) | kinds `ki`, `kj`; points `Ri`, `Rj`; `theta` | (n_i, n_j) array |
| `build_K` | full training covariance from `BLOCKS` | `theta` | (2792, 2792) array |
| `neg_log_posterior` | negative log marginal likelihood + Jeffreys prior | `theta` | scalar (NaN if Cholesky fails) |
| `nlp_safe` | same, NaN replaced by 10¹⁰ | `theta` | scalar |
| `run_nelder_mead` | Nelder–Mead from `x0` | `x0` | (theta, iterations) |
| `run_nm_then_lbfgs` | Nelder–Mead, then scaled L-BFGS-B, keeps the better result | `x0` | (theta, total iterations) |
| `factorize` | Cholesky of K and the weights alpha = K⁻¹ y | `th` | (`Lc`, `alpha`) |
| `predict` | posterior mean and std of one velocity component | `th`, `Lc`, `alpha`, `R_star`, `star` (`"u1"`, `"u2"`, `"u3"`) | (mean, std), each (n,) |
| `predict_mean` | posterior mean of any training kind, e.g. `"s"` or `"f1"` | `th`, `alpha`, `R_star`, `star` | (n,) |
| `predict_u` | `predict` for all three components | `th`, `Lc`, `alpha`, `R_star` | dict component → (mean, std) |
| `plane_grid` | grid on the x–y (axis 1) or x–z (axis 2) mid-plane | `axis` | (XX, HH, R) |
| `profile_line` | line across the pipe at `X_PROFILE` | `axis` | (h, R) |
| `u_exact` | Poiseuille velocity F(R0² − r²)/(4η) along x, 0 for y, z | `R` | dict of 3 arrays |
| `error_stats` | absolute and relative error tables per component | `pred`, `exact` | dict of two tables |
| `residual_stats` | div u and f_a − F_a of the posterior mean | `th`, `alpha`, `R` | dict of one table |
| `write_report` | writes and prints `error_stats.txt` | `path`, `header` lines, `sections` | none |
| `plotting_3d.plot_plane` | maps of mean, std and absolute error of u_x, u_y, u_z on a plane | grid, predictions, exact or `None`, axis label, wall outline, `out` | none (saves PNG) |
| `plotting_3d.plot_profiles` | u_x profiles across the pipe with a ±2σ band and the reference curve | `profiles` dict, `x_profile`, `out`, `ref_label` | none (saves PNG) |
| `reference_solutions` | reference velocity for each named point set: Poiseuille or cached FEM | dict name → (n, 3) points | dict name → {u1, u2, u3} |
| `fem_stokes_3d.get` | cached FEM reference at points | points (N, 3), cache path, `refit`, geometry and mesh settings | (u1, u2, u3, p), each (N,) |
| `fem_stokes_3d.solve` | builds the mesh, solves Stokes, samples the field | same as `get`, without the cache | (u1, u2, u3, p) |
| `fem_stokes_3d.build_mesh` | periodic tetrahedral pipe mesh | `L`, `a`, `avg_width`, `disk_refs`, `nx` | `MeshTet` |

### Coding conventions

- **Constants** are UPPER_CASE and sit at the top of the section that uses them; physical symbols keep their Greek names (`η`, `ΔP`).
- **Kernels** are plain functions `k(r, rp, t)`: unprimed operators act on `r`, primed ones on `rp`. `None` means an exactly zero covariance and passes through every combinator.
- **Block names** are short strings shared by `kfn`, `BLOCKS` and `predict`: `u1..u3`, `Su1..Su3`, `Sp`, `f1..f3`, `s`.
- **Precision and speed:** everything runs in float64; the objective and the prediction functions are `jax.jit`-compiled.
- **File name:** `3d_stokes_pigp.py` starts with a digit, so it can be run but not imported (`import 3d_stokes_pigp` is a syntax error). Rename it if tests or other scripts ever need to import it.

## Outputs

Everything is written to `output/<geometry>/` next to the script (`output/pipe/` or `output/sinusoidal/`), so the two geometries never overwrite each other. A second run of the same geometry overwrites its folder.

| File | Contents |
| --- | --- |
| `output/<geometry>/plane_xy.png` | u_x, u_y, u_z on the x–y mid-plane (z = 0): mean, std, absolute error against the reference |
| `output/<geometry>/plane_xz.png` | same on the x–z mid-plane (y = 0) |
| `output/<geometry>/profiles_ux.png` | u_x across the pipe at x = L/2 along y and along z, with ±2σ band and the reference curve (Poiseuille or FEM) |
| `output/<geometry>/errors/error_stats.txt` | error and residual statistics (below) |
| `output/<geometry>/results.npz` | `theta_init`, `theta_opt`, and for each plane `xy_X`, `xy_H`, `xy_u1_mean`, `xy_u1_std`, `xy_u1_ref`, … (same with `xz_`) |
| `output/sinusoidal/fem_reference.npz` | cached FEM velocity and pressure at all test points, with its fingerprint |

### error_stats.txt

The header gives the geometry and a, the number of training rows, the final objective and the definitions. Then one block per evaluation set:

- **Error, volume:** 4000 random points over the whole pipe.
- **Error, plane xy** and **error, plane xz:** the 61 × 41 plot grids (2501 points each).
- **PDE residual, volume:** div u and f_a − F_a of the posterior mean at the 4000 volume points.

Each error block has two tables, each with min, max, mean (of the signed value) and mean|·| (mean of its absolute value) for u_x, u_y, u_z:

| Table | Definition |
| --- | --- |
| absolute error | u_pred − u_ref |
| relative error | (u_pred − u_ref) / u_ref, set to 0 where u_ref = 0 |

u_ref is exact Poiseuille for the pipe and the FEM solution for the sinusoidal pipe.

## Validation and known limitations

- **Validation:** the straight pipe is compared with exact Poiseuille (peak 0.75), the sinusoidal pipe with the FEM reference (about 0.2% accurate). Only small PIGP test runs exist so far, so there are no PIGP accuracy numbers yet.
- **Relative error near zero:** u_x goes to 0 at the wall, so its relative error grows there (at the test margin 0.98 R, u_x ≈ 0.03 in the pipe). For the pipe, u_y = u_z = 0 everywhere, so their relative error is 0 by definition. For the sinusoidal pipe, the FEM u_y and u_z cross zero inside the pipe, so their relative error reaches values in the hundreds or thousands at those points; read the absolute table for u_y and u_z.
- **Cost:** each objective evaluation rebuilds K, including fourth-derivative f–f blocks, and runs an O(n³) Cholesky with n = 2792.
- **Conditioning:** K is badly conditioned; the jitter (EPS_JITTER² = 1e-6 on the diagonal) keeps the Cholesky stable. Small changes in θ can move the error noticeably.
- **Positive definiteness:** independent cross-kernels (u1–u2, …) do not guarantee a positive-definite K; the safeguards in Method handle failed evaluations but do not prevent them.
- **Objective vs accuracy:** a lower objective (e.g. after L-BFGS) does not always mean a lower error.
- **FEM cost:** the default FEM mesh needs about 6 GB of memory and 2 minutes, once per geometry; lower `FEM_DISK_REFS` and `FEM_NX` to 3 and 32 on a small machine (about 1 GB, 1% accuracy).
